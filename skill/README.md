# GUIDE - Claude Skill & Plugin

This folder packages [GUIDE](../) as a [Claude skill](https://docs.claude.com/en/docs/claude-code/skills) and an installable Claude Code plugin. The skill exposes GUIDE's 10 archetypes and 60 dimensions as reference-driven workflows for **designing** instructional content and **evaluating** existing artifacts. The plugin additionally bundles a **13-agent ADDIE pipeline** that orchestrates those archetypes end-to-end (see [Agent pipeline](#agent-pipeline-plugin)).

Version: **3.5.0** (tracks the GUIDE framework version one-to-one).

## Install

### Option A - Marketplace (recommended; receives version updates)

**GUI (easiest):** open **Settings -> Plugins** (under *Customize* in the sidebar), click **Add -> Add marketplace -> Add from a repository**, and enter `jermn007/GUIDE` (or `https://github.com/jermn007/GUIDE.git`). When the **Guide instructional design** plugin appears, install it.

**Slash commands:**

```
/plugin marketplace add jermn007/GUIDE
/plugin install guide-instructional-design@guide
```

Installing from the marketplace lets Claude Code update the plugin whenever a new `version` is published (see [Versioning](#versioning)), unlike a one-off file install, which is a fixed snapshot.

**Updating an existing install.** An already-added marketplace serves from a local clone, so a plain reinstall keeps the old version. Refresh the marketplace, then update the plugin:

```
/plugin marketplace update guide
/plugin update guide-instructional-design@guide
```

In the GUI, the plugin list shows each marketplace's **Last updated** date; re-sync the marketplace from its menu, then update the plugin.

### Option B - Plugin file (from a release)

Download the latest `guide-instructional-design.plugin` from the [Releases page](https://github.com/jermn007/GUIDE/releases/latest), then in Claude Code run:

```
/plugin install ./guide-instructional-design.plugin
```

For a step-by-step walkthrough with screenshots, see [`../Installing-GUIDE-in-Claude.pdf`](../Installing-GUIDE-in-Claude.pdf) (also attached to each release).

If you'd rather build the plugin from source (e.g., to test a local edit before a release):

```bash
# from the repo root
cd skill/guide-instructional-design-plugin
zip -r ../guide-instructional-design.plugin .
cd ../..
```

### Option C - Skill only

If you want just the skill (no plugin wrapper), drop the `guide-instructional-design/` folder into your skills directory:

- **User-level:** `~/.claude/skills/guide-instructional-design/`
- **Project-level:** `.claude/skills/guide-instructional-design/`

```bash
cp -r skill/guide-instructional-design ~/.claude/skills/
```

Or build a `.skill` zip for upload to Claude.ai / API skill stores:

```bash
cd skill
zip -r guide-instructional-design.skill guide-instructional-design
```

## Use

Once installed, the skill self-activates on instructional-design intents. Trigger phrases include: *course*, *training*, *lesson*, *module*, *learning objectives*, *quiz*, *rubric*, *assessment*, *e-learning*, *storyboard*, *needs analysis*, *accessibility (WCAG/UDL)*, or any of the named theorists (Bloom, Gagné, Mayer, Knowles, Sweller, Mager, Keller/ARCS, etc.).

It runs in two modes:

- **Design mode** - "write/build/design X" → author content with the relevant archetype's dimensions as forward-looking criteria, then self-check.
- **Evaluate mode** - "review/score/audit/critique X" → return a structured per-dimension scorecard with rationale, severity flags, and improvement suggestions.

The router in `SKILL.md` picks 1-3 archetypes per artifact and hands off to `EVALUATE.md` or `DESIGN.md`, so each run reads only its own mode. See `references/00_archetype_index.md` for the artifact→archetype map.

### Commands (plugin)

The plugin adds three commands you type. Claude never fires them on its own (`disable-model-invocation: true`), so they add nothing to Claude's context until you use them. In Claude Code they are namespaced, for example `/guide-instructional-design:guide-review`.

| Command | What it does |
|---------|--------------|
| `/guide-review <artifact>` | Scores the artifact in this conversation: one scorecard per archetype, plus archetype 10 when objectives, instruction, and assessment are all present. |
| `/guide-design <request>` | Runs the needs-analysis gatekeeper interview first (is training the right fix?), writes Mager objectives, then designs against the rubrics and self-checks. |
| `/guide-pipeline <request>` | Runs the 13-agent pipeline, with the main conversation as orchestrator: router, phase agents, fail-fast and acceptance gates, synthesizer, and the revision loop. Where subagents are unavailable, it runs the same plan in one conversation. |

The commands are plugin-only. The skill-only install (Option C) and claude.ai skill uploads keep the auto-triggering skill; there you ask in plain language instead.

## Agent pipeline (plugin)

Beyond the single-skill workflow above, the **plugin** bundles a 13-agent ADDIE pipeline that uses each GUIDE archetype as both a design guardrail (when building) and an acceptance test (when judging). The agent files live in [`guide-instructional-design-plugin/agents/`](guide-instructional-design-plugin/agents/) and are auto-discovered by Claude Code (no manifest entry required):

- **guide-router** - classifies the request (build / review / partial) and produces a dispatch plan.
- **10 archetype specialists** - `guide-needs-analysis` (07), `guide-sequencing` (03), `guide-story-design` (08), `guide-cognitive-neuro` (09), `guide-multimedia` (04), `guide-accessibility` (05), `guide-adult-learning` (01), `guide-assessment` (02), `guide-formative-eval` (06), and `guide-curriculum-alignment` (10, the acceptance gate that enforces the cap rule).
- **guide-synthesizer** - rolls every scorecard into a composite verdict, honoring archetype 10's cap rule and the ship/revise thresholds.
- **guide-reviser** - routes targeted feedback back to the responsible phase and loops until the composite clears threshold (max 3 iterations).

See [`guide-instructional-design-plugin/PIPELINE.md`](guide-instructional-design-plugin/PIPELINE.md) for the full workflow design - phase ordering, the Design→Develop fail-fast seam, severity flags, and the composite thresholds.

To drive the same pipeline programmatically (CI / batch evaluation rather than interactive design), use the Python orchestrator at the repo root, [`../guide_pipeline.py`](../guide_pipeline.py) (`ADDIEPipeline`); [`../smoke_test_pipeline.py`](../smoke_test_pipeline.py) is its mocked end-to-end test.

## Updating the references

The **single source of truth** for the handoff rubrics is [`../archetypes/handoff_0X_*.md`](../archetypes/) - the model-agnostic practitioner guides that live beside the Python judge modules. Edit those, never the copies under `references/`.

Everything below them is **generated - do not hand-edit**:

- `guide-instructional-design/references/handoff_0X_*.md` (the **skill edition**: canonical handoff minus the harness-only sections, plus a version footer)
- `guide-instructional-design-plugin/skills/.../references/handoff_0X_*.md` (plugin mirror)

The non-handoff skill files - `SKILL.md`, `package.json`, `references/00_archetype_index.md`, `references/NOTICE.md` - are skill-specific and edited **directly** in `guide-instructional-design/`; they are only mirrored into the plugin.

After editing the canonical handoffs or any skill file, run the build script:

```bash
python skill/build_skill.py
```

The script:

1. Writes the **skill edition** of each `../archetypes/handoff_*.md` into `references/`. It drops the sections that serve only the Python LLM-as-a-judge harness (`System Prompt (Judge Rubric)`, `Input Format`, `Calibration & Validation`, `Integration with GUIDE Pipeline`, `Version History`; see `HARNESS_ONLY_SECTIONS`), replaces the `Human Prompt Template` with the JSON output shape it contains (as `Output JSON`), and appends a fresh `Source: GUIDE ... (vX.Y.Z) ... Archetype NN of 10` footer. This cuts the ten rubrics by about a fifth. Claude scores from the scoring guide directly, so the judge prompt, a compressed restatement of that guide, only cost context.
2. Copies `../archetypes/discipline_alignment_crosswalk.md` with a generic version footer.
3. Mirrors the canonical skill into the plugin's `skills/` directory so the two stay byte-identical.
4. Checks that every specialist agent's output contract uses the same six dimension keys, in the same order, as its handoff's output JSON, and fails the build if not.

It does **not** touch the plugin's `agents/`, `PIPELINE.md`, or entry-command skills, which are plugin-only and maintained directly.

Because the skill edition omits the judge prompts, keep any scoring rule in the handoff's kept sections (scoring guide, severity flags, output format notes), not only in its judge prompt.

> **Note:** The Python judge prompts (`archetypes/*.py`, `JUDGE_SYSTEM_PROMPT`) and the handoff markdown are separate artifacts (an executable prompt vs. a practitioner guide) and are not generated from each other; keep their rubric content in step when editing either. `python test_judge_schemas.py` checks that each handoff's output JSON uses the same dimension keys as its Python judge.

## Versioning

Skill and plugin versions track the GUIDE framework version (currently 3.5.0). When bumping GUIDE:

1. Update `GUIDE_VERSION` in `build_skill.py`.
2. Update `version` and `claudeSkill.frameworkVersion` in `guide-instructional-design/package.json`.
3. Update `version` in `guide-instructional-design-plugin/.claude-plugin/plugin.json`.
4. Update the version strings in `SKILL.md`, `references/00_archetype_index.md`, and `references/NOTICE.md`.
5. Run `python skill/build_skill.py` to re-stamp the handoff footers and mirror the plugin.
6. Commit and push to `main`. Marketplace installs (Option A) pick up the new `version` from the plugin's `plugin.json`; file installs (Option B) require attaching the rebuilt `.plugin` to a release.

The marketplace manifest is `.claude-plugin/marketplace.json` at the repo root; it points at `skill/guide-instructional-design-plugin/` and does **not** carry its own per-plugin version (the plugin's `plugin.json` is the single version authority).
